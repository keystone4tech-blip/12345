# PROJECT_LOG.md

## Дата: 2026-05-19
### Исправление ошибки "Curve must be an instance of EllipticCurve" при отправке Web Push:
- **Суть проблемы**: В новых версиях библиотеки `cryptography` (установленной в Docker-окружении) вызов методов эллиптической кривой требует передачи экземпляра (`ec.SECP256R1()`), в то время как устаревшая библиотека `py-vapid` (зависимость `pywebpush`) и библиотека `http-ece` (шифрование данных Web Push) передавали класс кривой (`ec.SECP256R1`). Это вызывало падение сервера с `TypeError` при попытке отправить пуш-уведомления.
- **Реализованное решение**:
  - **Глобальный Monkey-Patch в `main.py`**: Добавлен перехватчик эллиптических методов `from_encoded_point`, `derive_private_key` и `generate_private_key` в самом начале `bot/main.py`. Если сторонняя библиотека передает класс кривой вместо инстанса, патч автоматически инстанцирует его. Это решило проблему обратной совместимости для абсолютно всех сторонних зависимостей (включая шифрование ECE внутри `http-ece`/`pywebpush`).
  - **Чистый криптографический VAPID**: Создан новый независимый модуль `bot/app/utils/vapid.py`, реализующий стандарт RFC 8292 и генерирующий VAPID JWT-токены напрямую через стандартные, стабильные методы библиотеки `cryptography`.
  - **Внедрение в роутеры**:
    - **`app/cabinet/routes/push.py`**: Обновлена логика отправки приветственного пуша. VAPID заголовки теперь генерируются на лету кастомной функцией и передаются через параметр `headers` функции `webpush()`.
    - **`app/cabinet/routes/notifications.py`**: Аналогично обновлен роутер `/test` для тестовых пушей пользователей.
  - Ошибки типизации эллиптической кривой полностью устранены, пуш-уведомления шифруются по протоколу ECE и успешно доставляются.

## Дата: 2026-05-18
### Исправление отображения Telegram HTML-тегов эмодзи:
- **Суть проблемы**: База данных содержит названия тарифов с тегами Telegram (например, `<tg-emoji emoji-id="...">👍</tg-emoji>`). В личном кабинете (React Web UI) эти теги отображались как сырой текст, что выглядело некорректно.
- **Реализованное решение**:
  - **Автоматический слой очистки (Pydantic-схемы)**: Во всех ключевых схемах (`schemas/subscription.py`, `schemas/tariffs.py`, `schemas/users.py`, `schemas/gift.py`), возвращающих названия тарифов или описания на фронтенд, внедрены валидаторы `@field_validator(..., mode='before')` с вызовом функции `strip_telegram_tags`.
  - **Явный слой очистки (Бэкенд роутеры)**: В роутерах подписок (`routes/subscription.py`) и реферальной сети (`routes/admin_referral_network.py`) добавлена безусловная очистка названий тарифов и сообщений об успешной покупке/смене тарифа.
  - Теперь названия тарифов в личном кабинете, истории покупок, графах реферальных связей и карточках подписок отображаются красиво и профессионально (без HTML-кода, только с чистыми эмодзи, например: `👍 Можно Всё`).
  - Успешно проверена локальная компиляция всех измененных модулей бэкенда.

## Дата: 2026-05-03 (Обновление 3)
### Исправление ошибок:
- **Пополнение баланса**: Исправлена ошибка, из-за которой администратор видел сообщение о неудаче при пополнении баланса, хотя деньги зачислялись. 
- Проблема заключалась в попытке отправить уведомление пользователю через `notification_delivery_service` после коммита транзакции без повторной загрузки связанных данных (подписки). Это вызывало ошибку `MissingGreenlet` (lazy load) в асинхронном контексте.
- В `user_service.py` заменен `db.refresh(user)` на `get_user_by_id(db, user_id)`, что гарантирует корректную загрузку всех необходимых полей для уведомления.
- Теперь уведомления о пополнении/списании баланса должны приходить пользователям корректно.
