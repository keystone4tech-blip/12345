## Дата: 2026-05-19 (Интеграция Web Push во все системные события бэкенда)
- **Суть проблемы**: Системные события бэкенда (пополнение баланса, изменение баланса, истечение или завершение подписки, начисление реферальных бонусов, регистрация рефералов, блокировки, автоплатежи и транзакции) отправлялись пользователям исключительно через Telegram Bot или по Email/WebSocket. При этом зарегистрированные в базе данных Web Push подписки (`PushSubscription`) пользователей PWA-приложения никак не использовались в реальной доставке уведомлений, из-за чего push-уведомления не доходили на телефоны и десктопы при установленном PWA.
- **Реализованное решение**:
  - **Бэкенд**: В сервисе `NotificationDeliveryService` (`bot/app/services/notification_delivery_service.py`) реализована полноценная отправка Web Push уведомлений на все активные зарегистрированные устройства пользователя:
    - Добавлен метод `_is_notification_enabled` для проверки и фильтрации уведомлений по индивидуальным предпочтениям пользователя (`notification_settings` из JSON-поля БД: истечение подписки, пороги низкого баланса, а также включение новостей или промо-рассылок).
    - Добавлен метод `_send_webpush_notification`, который:
      1. Извлекает все подписки (`PushSubscription`) пользователя из БД.
      2. Очищает от HTML-тегов текст уведомления (из переданного `telegram_message`) для формирования красивого нативного пуша.
      3. Подбирает релевантный заголовок (emoji, категория) и URL перехода в кабинете в зависимости от типа события (например, `/profile`, `/connection`, `/referral`).
      4. Выполняет шифрование ECE и отправляет пакет на удаленный пуш-сервер (Google, Apple, Mozilla) с использованием кастомных VAPID-заголовков.
      5. Обрабатывает исключение `WebPushException` и при коде ошибки `410 Gone` (подписка отозвана в браузере) автоматически удаляет устаревшую подписку из базы данных.
    - Интегрирован вызов Web Push во все ветки метода `send_notification`, благодаря чему пуши доставляются пользователям PWA независимо от того, привязан ли аккаунт Telegram или Email.
  - Успешно проверена локальная синтаксическая корректность и компиляция всех затронутых Python-файлов.

## Дата: 2026-05-19 (Обновление 3: Исправление импорта подписки во встроенном Webview приложения hApp/Hub)
- **Суть проблемы**: Когда пользователь открывал кабинет внутри встроенного Webview приложения hApp (Hub) и нажимал «Добавить подписку», вместо добавления происходил сброс страницы на главный экран. Фронтенд всегда заворачивал глубокую ссылку в промежуточную страницу `redirect.html` (созданную для обхода ограничений Telegram). Встроенные мобильные Webview блокируют JavaScript-перенаправления на кастомные протоколы (например, `happ://add/...`) после переходов по обычным HTTP-ссылкам, что ломало навигацию.
- **Реализованное решение**:
  - **Фронтенд**: В файле `cabinet/src/pages/Connection.tsx` логика функции `openDeepLink` разделена. Если пользователь находится в Telegram WebApp (`isTelegramWebApp === true`), он по-прежнему перенаправляется через `redirect.html`. В системном же браузере или встроенном Webview приложения hApp (`isTelegramWebApp === false`) теперь выполняется мгновенный **прямой переход** по нативной ссылке (`window.location.href = resolved`). Это позволяет приложению hApp перехватить протокол на нативном уровне до загрузки внешних документов, а обычному браузеру — мгновенно запустить приложение без лишних экранов ожидания.
  - Добавлено обязательное консольное логирование этапов перехода и подробные примечания на русском языке (`RULE[user_global]`).

## Дата: 2026-05-19 (Обновление 2: Исправление гонки автоподписки и залипания тумблера пушей)
- **Суть проблем**:
  1. При монтировании `AppShell` происходил фоновый вызов автоматической подписки на пуши до того, как завершалась первичная асинхронная проверка текущего статуса подписки в браузере (состояние `isPushSubscribed` изначально считалось `false`). Это приводило к повторному запросу `/subscribe` на бэкенд при каждом открытии приложения, из-за чего пользователю каждый раз повторно отправлялось приветственное уведомление с поздравлением.
  2. Переключатель пушей (`Switch`) визуально залипал: цвет менялся, но ползунок (круг) не сдвигался вправо. Это происходило из-за конфликта анимированного `motion.span asChild` (из Framer Motion, который некорректно рассчитывал макеты в Telegram/Safari WebView) со стандартным CSS-сдвигом `SwitchPrimitive.Thumb`.
- **Реализованное решение**:
  - **Фронтенд**:
    - В `AppShell.tsx` эффект автоподписки теперь ожидает завершения первичной проверки (`if (pushLoading) return`). Запрос автоподписки выполняется только в том случае, если проверка завершена и пользователь действительно не подписан (`!isPushSubscribed`).
    - В `Switch.tsx` удален `<motion.span asChild>` и `springTransition`. Thumb переписан на чистый, стабильный и высокопроизводительный CSS-переход Radix UI с классами `transition-transform duration-200 ease-in-out` и `data-[state=checked]:translate-x-5`. Это полностью решило проблему залипания на любых устройствах.
  - **Бэкенд**:
    - В `bot/app/cabinet/routes/push.py` добавлена проверка `is_new`. Приветственное push-уведомление теперь отправляется **исключительно** при создании новой подписки (`is_new = True`). Если существующая подписка просто обновляется (при смене сессии или входе), поздравление не отправляется.

## Дата: 2026-05-19
### Исправление ошибки "Curve must be an instance of EllipticCurve" при отправке Web Push:
- **Суть проблемы**: В новых версиях библиотеки `cryptography` (установленной в Docker-окружении) вызов методов эллиптической кривой требует передачи экземпляра (`ec.SECP256R1()`), в то время как устаревшая библиотека `py-vapid` (зависимость `pywebpush`) и библиотека `http-ece` (шифрование данных Web Push) передавали класс кривой (`ec.SECP256R1`). Это вызывало падение сервера с `TypeError` при попытке отправить пуш-уведомления.
- **Реализованное решение**:
  - **Глобальный Monkey-Patch в `main.py`**: Добавлен перехватчик эллиптических методов `from_encoded_point`, `derive_private_key` и `generate_private_key` в самом начале `bot/main.py`. Если сторонняя библиотека передает класс кривой вместо инстанса, патч автоматически инстанцирует его. Это решило проблему обратной совместимости для абсолютно всех сторонних зависимостей (включая шифрование ECE внутри `http-ece`/`pywebpush`).
  - **Чистый криптографический VAPID**: Создан новый независимый модуль `bot/app/utils/vapid.py`, реализующий стандарт RFC 8292 и генерирующий VAPID JWT-токены напрямую через стандартные, стабильные методы библиотеки `cryptography`.
  - **Внедрение в роутеры**:
    - **`app/cabinet/routes/push.py`**: Обновлена логика отправки приветственного пуша. VAPID заголовки теперь генерируются на лету кастомной функцией и передаются через параметр `headers` функции `webpush()`.
    - **`app/cabinet/routes/notifications.py`**: Аналогично обновлен роутер `/test` для тестовых пушей пользователей.
  - Ошибки типизации эллиптической кривой полностью устранены, пуш-уведомления шифруются по протоколу ECE и успешно доставляются.

## Дата: 2026-05-18
### Исправление отображения Telegram HTML-тегов эмодзи:
- **Суть проблемы**: База данных содержит названия тарифов с тегами Telegram (например, `<tg-emoji emoji-id="...">👍</tg-emoji>`). В личном кабинете (React Web UI) эти теги отображались как сырой текст, что выглядело некорректно.

  - **Явный слой очистки (Бэкенд роутеры)**: В роутерах подписок (`routes/subscription.py`) и реферальной сети (`routes/admin_referral_network.py`) добавлена безусловная очистка названий тарифов и сообщений об успешной покупке/смене тарифа.
  - Теперь названия тарифов в личном кабинете, истории покупок, графах реферальных связей и карточках подписок отображаются красиво и профессионально (без HTML-кода, только с чистыми эмодзи, например: `👍 Можно Всё`).
